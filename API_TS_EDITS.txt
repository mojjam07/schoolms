Fix for the console line "POST /api/auth/refresh 401 (Unauthorized)"

That request is the app asking "am I still signed in?" when it loads. When you are signed out, the answer is a correct 401, and the
browser prints every failed request in red. The fixed client/src/lib/api.ts in this zip skips the request when nobody was signed in,
using a harmless flag in localStorage (no token is stored there; the secure cookie is still the real session).

Apply it by copying client/src/lib/api.ts over yours. It is your Phase 9 copy plus three small changes:
  1. a `hint` helper (get / set / clear the flag "kok_session")
  2. setAccessToken sets the flag when given a token and clears it on sign-out
  3. refreshSession returns null at once when the flag is not set, sets it on success, and clears it when the server answers 401

Notes
- Anyone already signed in when you deploy this is treated as signed out once, and signs in again. After that it works normally.
- If you had edited api.ts since Phase 9, make the three changes by hand instead of copying the file.
- If you are signed in and a reload still sends you to the sign-in page, that is a different bug (the cookie is not being kept).
  Check DevTools > Application > Cookies for localhost:5173, and that the cookie is not marked Secure in development.
